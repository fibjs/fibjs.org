Groupon Rebuilds Its Entire Web Tier on Node.js

Adam Geitgey was the first participant in the Node Foundation's Enterprise Conversations series; he has spent five years as a software engineering manager at Groupon, one of the largest e-commerce companies.

When he first joined the company, it was still an online store built mainly on Ruby on Rails, and everything had to run as one giant monolithic application. That worked fine for a long time, but in the end it became harder and harder to maintain, and it looked as though they would have to give up on it.

On top of that, Groupon made a number of acquisitions in recent years, so in addition to their Ruby on Rails stack, they ended up with a new Java stack in Europe and a PHP stack in South America.

Groupon realized it needed to replace its current stack, so about three to four years ago it started looking for a more suitable software platform.

Why They Chose Node

Groupon decided to adopt Node.js for the following reasons:

  • JavaScript is close to a universal language, so it costs less to learn and work with, and developers can communicate with one another more easily.

  • Scaling Node.js applications held up well in testing. Node not only unified their development language, but in some cases also gave them better performance.

  • Node developers can reuse code they have already written, which proves extremely convenient from time to time.

  • Node.js is the most unified platform at Groupon; even though they wrote many backend services in Java, the Java frameworks and approaches they used varied widely. Node.js, however, offered a way to move a large piece of software onto a single platform in one go.

Groupon's engineering team ultimately decided to rebuild the entire web tier on Node.js. During the rewrite, Adam's job was to manage the team's development platform as well as the framework other teams used to build and ship Node applications in production.

The team also released several open-source libraries that they built along the way: The team also released several of its own open-source libraries along the way:

  • gofer, an API client library for talking to backend services.

  • node cached, a caching library for Node.js.

Today Groupon uses Node across several platforms:

  • Roughly 300 to 400 backend services run Node.js mixed with Java and Ruby.

  • They use Node as an API integration layer.

  • All of their client apps, including the website, use Node.

Currently Groupon has 70 Node.js apps in production, and these apps are used in 30 countries. Overall, Groupon relies heavily on Node.js on the front end, with a few backend uses scattered here and there.

The Future of Node at Groupon

As for the future, they are fully convinced that Node is worth investing in for their web platform. All of their products and services are now built on Node 4, but they have long been looking forward to Node 6 and are still waiting for the long-term support release to arrive.

In the past, because Groupon used Ruby, they had also ended up using a great deal of CoffeeScript; this was a perfect opportunity to finally move away from CoffeeScript and standardize on plain JavaScript.

Another big project Groupon is working on is moving from a model where developers maintain their own servers to a model where the company provides them with clusters of servers and their apps run on them - more like a Heroku model. Another big project Groupon is working on is the move from a model in which developers maintain their own servers to one in which apps run on clusters of servers provided by the company — much more like the Heroku model.

Node.js: The Glue at Skycatch

Andre Deutmeyer is the next participant in the Node Foundation's Enterprise Conversations series; his role at Skycatch is to lead the web infrastructure and development teams.

Skycatch is a data company that helps capture, manage, and analyze commercial drone data, treating a construction or mining site as a database to be queried. Existing tools — such as writing raw SQL queries — are very difficult and time-consuming, but the company's solution makes it effortless to extract actionable data from a site.

Skycatch has a small cross-functional team of 20 developers, and as I mentioned, Andre's role is to lead the web, infrastructure, and development teams. He is involved in architecting and scaling the data processing, because his goal is to deliver the data you send reliably and in a timely manner.

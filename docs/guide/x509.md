# Using X509 Certificates in fibjs

## Background

### What Is an x509 Certificate

An x509 certificate is the most commonly used digital certificate format in the internationally standardized public key infrastructure (PKI) system. It can be used for authentication and encryption and is widely used on the Internet in SSL/TLS and other types of network applications. x509 certificates use a public/private key authentication mechanism and can guarantee the confidentiality, integrity, and authenticity of data transmission.

### Where Are x509 Certificates Used

On the Internet, the most common use case for x509 certificates is certificate authentication in the TLS/SSL protocol, which ensures that data transmitted between the client and the server is encrypted over a secure channel and has been verified. x509 certificates can also be used for identity authentication in application protocols based on public/private key encryption, such as VPN and SSH.

### fibjs Support for X509 Certificates

fibjs supports working with x509 certificates. It provides classes such as `X509Certificate` and `X509CertificateRequest` in the `crypto` module for reading, creating, and signing certificates. These classes let you obtain information such as a certificate's validity period, public key, issuer, and subject name, as well as sign and verify certificates. In addition, fibjs provides the `HttpsServer` class to support certificate authentication and encrypted connections for HTTPS, making it easier to use x509 certificates in fibjs.

## Introducing the X509 Module

### What Is the X509 Module

The `crypto` module in fibjs provides classes such as `X509Certificate` and `X509CertificateRequest` for reading, creating, and signing x509 certificates. The X509 module is a module for processing x509 certificates, providing operations such as parsing, creating, and verifying certificates.

### What the X509 Module Does

The X509 module is used to operate on x509 certificates. You can use it to read an existing x509 certificate and obtain information such as the certificate's validity period, public key, issuer, and subject name. The X509 module can also create x509 certificate requests and sign certificates, for purposes such as certificate authentication in the TLS/SSL protocol.

### X509 Module APIs

The following is a list of the more important APIs in the X509 module:

- `X509Certificate`: A class for reading and operating on x509 certificates.
- `X509CertificateRequest`: A class for creating x509 certificate requests.
- `verify`: Verifies an x509 certificate using a CA certificate.
- `HttpsServer`: A class that provides an authentication service based on x509 certificates.
- `TLSSocket`: A class for sending and receiving data over a socket, providing an authentication service based on x509 certificates.

### Example Code

The following is example code for reading an x509 certificate and creating an x509 certificate request:

```JavaScript
const crypto = require('crypto');
const fs = require('fs');

// load the cert
const cert = new crypto.X509Certificate(fs.readFileSync('server.crt'));
console.log(cert.subject);

// create x509 certificate request
let pkey = crypto.createPrivateKey(fs.readFileSync('private.pem'));
let req = crypto.createCertificateRequest({
    key: pkey,
    subject: {
        C: "CN",
        O: "fibjs",
        CN: "localhost"
    }
});
let pemReq = req.pem;
console.log(pemReq);
```

The example code above reads an existing x509 certificate through the `X509Certificate` class and outputs the certificate's subject name, `subject`. It also demonstrates how to create an x509 certificate request through `X509CertificateRequest` and outputs the request information in PEM format.

## Using the X509 Module

### Generating a Self-Signed Certificate

Generating a self-signed certificate is fairly simple; it generally involves the following steps:

- Generate a `KeyObject` (private key)
- Generate an `X509CertificateRequest` (certificate request)
- Use the `X509CertificateRequest` to generate an `X509Certificate` (the actual certificate)
- Save the certificate

With these steps, you can generate an x509 certificate for testing and development environments. The specific implementation is as follows:

Use the following code to create a `KeyObject`. The `from()` method can create a `KeyObject` from a PEM-format string or a Buffer.

```JavaScript
const crypto = require('crypto');
const fs = require('fs');
const pkey = crypto.createPrivateKey(fs.readFileSync('private.pem'));
```

Use the following code to create an `X509CertificateRequest`. The first parameter of `X509CertificateRequest` is the subject distinguished name (Subject Name), in the string format key1=value1,key2=value2. The second parameter is the `KeyObject` created earlier, which is used to sign the certificate. For example:

```JavaScript
let xrq = crypto.createCertificateRequest({
    key: pkey,
    subject: {
        C: "CN",
        O: "fibjs",
        CN: "localhost"
    }
});
```

Use the following code to create an `X509Certificate` (the actual certificate). This is done by calling the `issue` method of `X509CertificateRequest`, which accepts three parameters: the name of the certificate issuer, the `KeyObject` used for signing, and other related information. For example, in the following example, the `X509CertificateRequest` object is signed as a self-signed certificate, with itself as the signing authority and a certificate validity period of 10 years:

```JavaScript
const opt = {
  notBefore: new Date(),
  notAfter: new Date(new Date().getTime() + 10 * 365 * 24 * 60 * 60 * 1000)
};
const cert = xrq.issue({
    key: pkey,
    issuer: {
        C: "CN",
        O: "fibjs",
        CN: "localhost"
    },
    ...opt
});
```

Use the following code to save the `KeyObject` and the `X509Certificate` to local files. Because the certificate is stored in PEM format, you can use the `export` method to convert the certificate object into a string and then save it directly to a file:

```JavaScript
const ks = pkey.export({ format: "pem" });    // export pem format data of the private key
const cs = cert.pem; // export pem format data of the cert
fs.writeFileSync('mycert.key', ks); // save the key
fs.writeFileSync('mycert.pem', cs); // save the cert
```

The code above completes the entire process from generating a private key to storing a self-signed certificate. You can use this certificate to test and develop security-related applications.

### Loading Certificates

Loading certificates is an important operation when using x509 certificates. The following describes how to load certificate files and how to load public and private keys.

To use an x509 certificate, you must first read the certificate file into memory and convert it into an x509 certificate object. The steps for loading a certificate file are as follows:

In a fibjs JavaScript program, you can use the relevant APIs of the `fs` module to read files. For example, use the following code to read a PEM-format certificate file:

```JavaScript
const fs = require('fs');
const certData = fs.readFileSync('server.crt');
```

After reading the file, you must use an `X509Certificate` object to convert the certificate file contents into an x509 certificate:

```JavaScript
const crypto = require('crypto');
const cert = new crypto.X509Certificate(certData);
```

After the steps above, the local x509 certificate file is loaded.

An x509 certificate stores a public key and encrypted signature information, so when using a certificate you need to extract the public key from the certificate to facilitate encrypting and decrypting data. The `KeyObject` class can convert a PEM-format public/private key string into a public/private key object. You can use the following code to read PEM-format public/private key strings and create a `KeyObject` object:

```JavaScript
const privateKey = fs.readFileSync('private.pem'); // load the data from file
const pKey = crypto.createPrivateKey(privateKey); // load from pem format data
```

After the steps above, the public/private key file is converted into a `KeyObject` object.

### Parsing Certificates

A certificate is an important part of SSL/TLS interactions, used for identity authentication and encryption of data transmission. Now let's look at how to parse a certificate in fibjs.

You can use the `X509Certificate` class of the `crypto` module to build a certificate object by reading a DER/PEM-format certificate file, and then obtain some basic information about the certificate, such as its subject name, issuer name, validity period, and so on.

Example code:

```JavaScript
const crypto = require('crypto');
const fs = require('fs');

const cert = new crypto.X509Certificate(fs.readFileSync('path/to/cert.pem'));

const subjectName = cert.subject;
const issuerName = cert.issuer;
const validFromDate = cert.validFrom;
const expirationDate = cert.validTo;
const serialNumber = cert.serialNumber;

console.log(`Certificate subject name: ${subjectName}`);
console.log(`Certificate issuer name: ${issuerName}`);
console.log(`Certificate validity period: ${validFromDate} ~ ${expirationDate}`);
console.log(`Certificate serial number: ${serialNumber}`);
```

When you need to use a certificate, you need to verify that it is legitimate. The key is to determine that the certificate was issued by a trusted organization. You can use the `verify` method of `X509Certificate` to check the certificate's validity; a common verification method is to verify the certificate chain to ensure that the certificate was issued by a trusted CA.

Example code:

```JavaScript
const caCert = new crypto.X509Certificate(fs.readFileSync('path/to/ca.crt'));

const verifyResult = cert.verify(caCert.publicKey);

if (!verifyResult) {
  console.error('Certificate verification failed');
} else {
  console.log('Certificate verification passed');
}
```

In this example code, we first read the specified CA certificate, create an `X509Certificate` object, and then use the `verify` method on the certificate object to verify the certificate in question and obtain the verification result. You can determine whether the certificate is legitimate by checking whether the verification result is `true`. If the result is `false`, verification has failed, and you should stop using that certificate.

### Using Certificates

When using an HTTPS server, make sure the certificate you are using has been added to the server. The following is a simple example that loads a certificate and a private key file through the `crypto` module:

```JavaScript
const http = require("http");
const crypto = require("crypto");
const fs = require("fs");

const cert = new crypto.X509Certificate(fs.readFileSync("server.crt"));
const key = crypto.createPrivateKey(fs.readFileSync("server.key"));

const server = new http.HttpsServer({
    cert: cert,
    key: key,
    port: 8443
}, function(req) {
    req.response.write(`Hello, fibjs!`);
});
server.start();
```

In the example above, we used `X509Certificate` and `createPrivateKey` to load the `server.crt` and `server.key` files, then created a service with the `HttpsServer` object and started it with the loaded certificate and key files.

## Notes on the X509 Module

### Certificate Security

The X509 module provides functions such as creating and handling certificates, and certificate security must be guaranteed. Pay particular attention to the following points:

- Private key security. The private key is an important part of a certificate and must be strictly protected. When using a certificate, store the private key in a secure place whenever possible and set appropriate access permissions.
- Certificate transmission security. During the exchange and use of certificates, secure transmission methods must be used to prevent the certificate from being stolen or tampered with.
- Certificate verification security. Certificate verification is an important part of ensuring that a certificate is valid and secure. Verification must be carried out strictly according to certificate validation rules to avoid being misled by forged certificates.

### Certificate Validity Period

The validity period of a certificate is the time between the certificate's issue date and its expiration date. The validity period limits how long a certificate can be used: before the certificate expires, the certificate holder can use it, but after the certificate expires, it loses its validity.

Therefore, before using a certificate, you must first check its validity period to avoid using an expired certificate. At the same time, you should renew the certificate as early as possible before it expires to ensure its availability.

### Certificate Trust Mechanism

The certificate trust mechanism is the key factor in whether a certificate can be trusted by a client or a server. Usually, a client or server only trusts certificates issued and recognized by a trusted authority (CA).

Before using a certificate, you must resolve the question of trust. You can determine whether a certificate is trustworthy by checking the certificate's issuer, its subject distinguished name, and other information.

### Certificate Renewal Mechanism

The certificate renewal mechanism is an important part of ensuring that certificates remain valid and secure. Usually, certificate renewal mainly covers two aspects:

- Renewal after the certificate expires. After a certificate expires, you must apply for a new certificate and perform signing and verification according to the corresponding rules to ensure the certificate's validity.
- Certificate extension and updating. While using a certificate, if you need to extend or update its information, you can do so by applying for a new certificate and performing signing and verification.

In summary, the X509 module provides functions such as creating and handling certificates and is an important part of ensuring that certificates are secure, trustworthy, and valid. When using and managing certificates, you must follow the corresponding rules and requirements to ensure their validity and security.
